## Context

见 [proposal.md](proposal.md)。当前 `presentation.py` 在模块顶层导入 Rich，CLI 也从中导入错误脱敏函数；仅把 Textual 移到 extra 不能得到独立 CLI。`bootstrap.py` 无条件检查 ManagerApp 和样式，shell 包装器尚未传递安装参数。TUI 已有四页、后台任务和安全确认，本次复用这些交互与操作服务。

当前工作区包含前序实现的未提交修改，本轮只新增本变更目录。三个能力的基线来自 `add-textual-tui-and-command-tables/specs/`；主规格尚未建立，未来同步必须按前序、本变更的顺序进行，不重复创建同名能力。

## Goals / Non-Goals

**Goals:**

- 没有 Textual / Rich 的独立环境能运行全部 CLI 操作及帮助；安装界面不是运行 CLI 的前提。
- 将主题、布局、状态语义分开，四页及弹窗采用同一套设计规则。
- 在 80×24、120×36、中英文及无颜色模式下保持可操作；安全与脚本接口不回退。

**Non-Goals:**

- 不改代理切换、Doctor、回滚、存储和真实 Codex 执行逻辑，不增加自动依赖安装。
- 不引入主题商店、用户主题配置、多框架输出、动画面板或新诊断能力。
- “零运行依赖”不等于不需要 venv/pip 或完全离线安装；构建仍需要打包工具。本次不恢复旧的源码复制安装方式。

## Decisions

### 1. 一份包，两种安装模式

`dependencies = []`；`[project.optional-dependencies].tui` 保持现有约束 `textual>=8.2.8,<9`、`rich>=14.2.0,<15`。测试依赖不隐式引入 UI，完整开发环境显式安装 `.[test,tui]`。样式作为小型包资源随包分发，但轻量版不导入或要求 UI 框架。

| 用途 | 仓库安装器 | 同一目标 Python 环境中的 pip |
| --- | --- | --- |
| 轻量 CLI（默认） | `./scripts/install.sh` | `python3 -m pip install .` |
| CLI + TUI | `./scripts/install.sh --with-tui` | `python3 -m pip install '.[tui]'` |

安装参数显式传递到 bootstrap；增加安装器 `--help`，未知参数在创建环境前失败。每次 shell 安装都以本次参数为准：无参数安装轻量版，包括从完整版切回轻量版；保留旧 venv 和配置，不删除或卸载旧环境。成功信息说明安装类型、启动方式及补装方式。pip 不保证移除已安装的 extra；需要严格轻量时使用新的独立环境或默认 shell 安装器。

继续先创建新环境、安装、预检，再发布入口。基础预检只验证 CLI、核心导入和 Codex 发现；完整预检再验证 UI 依赖、入口和样式。失败保留旧入口，不能把完整安装失败静默降级为 CLI。补装通过重新运行完整安装器创建新环境，不在当前受管 venv 中现场 pip 安装。

未选方案：CLI 保留 Rich 会违反已确认的零运行依赖；分别维护两个包会增加发布与版本匹配成本。

### 2. 启动与渲染解耦

| 场景 | 无参数（含仅指定语言） | 显式 `tui` |
| --- | --- | --- |
| 轻量、交互终端 | CLI 帮助，返回 0 | 双语补装提示，返回 2 |
| UI 可用、交互终端 | 打开 TUI | 打开 TUI |
| 非交互或 `TERM=dumb` | 纯文本帮助，返回 0 | 终端要求说明，返回 2 |

帮助、普通子命令和 JSON 分支不导入 UI。仅到交互入口时探测所需依赖；确实缺少可选依赖与包内部导入错误要区分，不能用宽泛异常捕获把程序缺陷都报告成“未安装”。已安装但损坏的 UI 给出错误和修复提示，不宣称成功进入界面。探测、缺失提示和帮助不初始化配置、不联网。

`presentation.py` 改为标准库 CLI 表格；Rich 手册渲染移到只由 TUI 加载的模块。`safe_error` 保持标准库可用，CLI 与 UI 复用脱敏逻辑。目录文案继续来自 `catalog.py`，`tui` 在轻量版帮助中保留并标明选装。

CLI 在两种安装模式下输出一致的纯文本，不因环境恰好存在 Rich 而改变样式。使用标准库 Unicode 宽度处理中文、组合字符与制表符，按终端宽度折行；窄屏仍保留所有单元格内容，长 URL 不省略。特殊 emoji 字形宽度由终端决定，不宣称像素级对齐。JSON 直接沿用原输出路径，不经过表格或翻译层。

### 3. 设计路线与整体结构

使用 `designing-tuis` 默认路线，目标框架 Textual；本轮完成 Grounding / Planning，代码生成和实机预览留到 apply，不创建无需求的 `.tui` 中间格式。用户已确认石墨黑工作台方向。

Phase 1：四个顶层区域，无包围整个屏幕的装饰边框。标题和导航不铺强调色；正文靠面板标题、细线和间距分组；底部始终保留操作状态和快捷键。

Phase 2 布局树（比例按正文可用宽度计算）：

```text
Screen · column
├─ Header · 2 rows：项目名 / 当前配置 / 语言（不代表实时连通）
├─ Tabs · 3 rows：[代理管理] 诊断 维护 命令手册
├─ Body · fill，面板内部 horizontal padding 1，间隔 1 column
│  ├─ Primary · 65%，min 48 columns：列表或主要内容
│  └─ Detail  · 35%，min 28 columns：详情、提示、相关操作
└─ Footer · 2 rows：阶段摘要 / 上下文快捷键
```

宽度 >=100 时代理和手册采用双栏；宽度 <100 时改为上下布局。80×24 下标题、导航、页脚共 7 行，正文约 17 行：代理表格约 8 行，其余用于详情摘要与紧凑按钮；长详情和附加操作在正文内滚动，Tab 聚焦会滚入可视区。弹窗宽度约 70%、最小 48 列、最大不超过视口减边距，内容区可滚动，确认／取消始终可达。低于 80×24 显示尺寸提示并保持退出通道，不承诺完整布局。

宽屏示意（结构线框，不是已渲染的新界面）：

```text
Codex SOCKS Manager                         当前: office  ·  zh-CN
[代理管理]  诊断  维护  命令手册
┌ 代理配置 ──────────────────────────┐ ┌ 所选配置 ───────────┐
│ 状态   名称     协议   代理地址    │ │ office              │
│ *当前  office   socks5 …           │ │ socks5              │
│ —      local    http   …           │ │ 脱敏地址，完整换行  │
│                                    │ │ 配置不等于连通证明  │
│                                    │ │ [应用] [编辑]       │
│                                    │ │ [新增] [关闭] [删除]│
└────────────────────────────────────┘ └─────────────────────┘
就绪 · 尚未检查
a 新增  e 编辑  r 刷新  l 语言  q 退出  ·  Tab / 方向键 / Enter
```

线框中的省略号仅为标注占位，产品中脱敏地址必须可完整查看。没有固定左侧导航栏，避免四个页面占用一整列；没有全屏装饰框，减少窄屏损耗。

### 4. 主题与组件语言

集中定义语义 token，组件引用 token，不再散落硬编码颜色。下表是设计起点，实施时用实际组合校验对比度并微调。

| Token | 初始色值 | 用途 |
| --- | --- | --- |
| background | `#17191C` | 石墨黑底色 |
| surface | `#202328` | 面板和弹窗 |
| text | `#EEECE6` | 暖白正文与标题 |
| muted | `#ADB2BA` | 次级说明，不叠加 dim |
| border | `#737D8C` | 细单线边框、分隔 |
| accent | `#9CCBFF` | 冰蓝焦点与当前导航 |
| selection | `#303F52` | 选中行背景，正文仍用暖白 |
| warning | `#EBC073` | 警告文字、图标 |
| error | `#F29B97` | 错误文字、图标 |

正文对比度目标 >=4.5:1；必要边框和焦点标记 >=3:1。高亮行带 `>` 标记或等效非颜色焦点提示；实际活动配置仍用独立 `* 当前`。导航使用括号／下划线加粗，不能只靠颜色。成功使用文字和符号，不新增大块绿色；警告、错误只在语义发生时用橙红，默认按钮均为中性色，仅当前主要操作强调。取消默认获得危险操作弹窗焦点。

保留键盘、鼠标、输入框快捷键隔离；移除按钮默认渐变感或多色厚边。表头暖白加粗，表格不用大面积彩色斑马纹；边框统一单线，避免双线、圆角混用。`NO_COLOR` 下采用文本标记、反显或边框区分状态；依赖 Textual 自身合成器处理重绘，不手工输出清屏转义打断框架。

### 5. 四页与状态设计

| 页面 | 主区 | 详情／操作 |
| --- | --- | --- |
| 代理管理 | 四列表头、活动标记、焦点标记、空状态引导 | 所选名称、协议、完整脱敏 URL；应用为主操作，编辑说明“仅保存” |
| 诊断 | HTTPS、WSS、app-server、代理环境的标签化结果行 | 分类解释、检查状态、手动运行；初始“尚未检查”，旧结果明确过期 |
| 维护 | launcher／备份与恢复／更新与迁移分组；不堆积彩色按钮 | 每项简短影响说明，恢复保留快照选择与手工路径 |
| 命令手册 | 筛选输入、命令／功能／示例表格 | 参数、边界、更多示例，宽屏右侧、窄屏下方 |

新增／编辑表单沿用校验和默认隐藏 URL；确认弹窗明确目标及副作用。页脚常驻阶段摘要，长错误在可滚动结果区完整展示而非仅瞬时通知；显示真实“回滚完成／回滚失败”，执行结束前禁止重复提交和普通退出。重排组件不替换操作服务、不改变确认条件。

### 6. 验证设计

基础环境显式不安装 Textual / Rich，运行 CLI 和核心测试并检查已安装包与导入集合；完整环境装 `.[test,tui]` 跑全部测试。CI 保持 Python 3.10／3.12，增加安装模式维度，不允许因统一装了 UI 而掩盖基础依赖缺失。

安装集成覆盖 CLI→TUI→CLI、新版替换旧版、缺 venv、依赖／预检／发布失败保护；使用临时 XDG、离线 wheel 源和 fake Codex。基础测试仅在明确的 CLI job 中排除 UI 测试；完整 job 必须收集并运行 UI 测试。

Pilot 覆盖四页、表单、确认与取消、操作中／回滚中、语言、长内容与焦点；在 80×24 和 120×36 输出安全假数据预览。比较顺序遵循 skill：布局／比例／重绘 P0 → 组件 P1 → 内容 P2 → 样式 P3 → 间距 P4，每轮修复一类；宽屏比例偏差不超过 10%。检查往返缩放、滚动、切页、灰度和对比度；任何 P0/P1 问题不得通过视觉验收。当前只查看了旧版预览，未生成新版运行截图。

## Risks / Trade-offs

- 标准库表格需要自行处理 CJK 宽度 → 独立小型渲染器和中英文长内容测试，不用字符数代替显示列宽。
- 默认重装会从完整模式切回 CLI → 安装帮助和成功信息明确模式，文档要求完整模式升级继续使用 `--with-tui`；不删除旧 venv。
- 基础包仍包含少量 UI 源码／样式 → 轻量承诺针对运行依赖，不拆分发行包；包资源测试保证选装后可直接用。
- 主题效果受终端调色和字体影响 → 校验 token 对比度与灰度可读性，预览不冒充所有终端的像素保证。
- 既有规格尚未归档 → 保留前序文件，归档时按依赖顺序同步；当前严格校验不等于主规格已完成合并。

## Migration Plan

实施依次完成渲染解耦、可选依赖与分流、安装器、样式重构、双模式验证、文档。发布说明标出默认安装变化和选装命令。已有 profile、settings 和快照无需数据迁移；shell 安装仍在新环境预检后切换解释器与入口，发布失败恢复原入口和配置，旧环境保留。不得直接对真实环境演练切换或恢复。

本轮仅交付 proposal、design、三个增量 specs 和 tasks。后续经用户要求 apply 后才实现；归档或同步另按 OpenSpec 工作流处理。
